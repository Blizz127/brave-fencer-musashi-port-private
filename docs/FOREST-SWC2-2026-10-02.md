# Forest flicker: SWC2 register bank correction (2026-10-02)

Codex, sole writer for Devbox task `df2840be6532`.

## Cause and change

The interpreter special-cased SWC2 at `80048E98` and `80048FA8` to read
control register 11. Both instructions must read data register 11 (IR3).
These are the final matrix stores in MulMatrix/MulMatrix2; the exception
put a lighting coefficient into the final rotation matrix element.

The hardware contract is in Sony's *Inline Programming Reference*, November
1998, pp. 4-3/4-4: SWC2 transfers a GTE data register to memory. Data 11 is
IR3, while control 11 contains lighting matrix elements L31/L32.
[Sony reference PDF, page 81](https://psx.arthus.net/sdk/Psy-Q/DOCS/Devrefs/Inlinref.pdf#page=81).
No SDK implementation was copied.

The camera path reaches `80048D9C` through `80054DCC` and stores to
`800AE688` (bad final element at `800AE698`). The object path through
`8001FC08`, `80054AAC`, `80054DA4` and `80052FCC` reaches `80048EAC`.
Both matrix routines execute in the interpreter in the release configuration.
The patch removes the wrong-bank exception. Admission, caller checks, address
checks, instruction charging and failure behavior are otherwise unchanged.

## Regression evidence

from an identity multiplication whose correct final element is 37. Correcting
that expectation failed against the old runtime, then passed with the fix.

-32768, stale upper bits, distinct lighting state, absent control callback,
and absent data callback (refusal without CPU/RAM/clock effects). A mutant
restores the erroneous bank selection and must fail. Existing identity matrix,
